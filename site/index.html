Check proxies against specific targets.

Proxycheck runs HTTP requests through HTTP and SOCKS proxies and checks the responses against a preset. Use it from the command line or through the HTTP API.

Quick start ↗GitHub ↗

Presets

A preset defines which URLs to request and what to expect from the responses.

proxycheck run -p youtube proxies.txt

Requests oEmbed metadata and downloads at least 8 KiB from YouTube’s image CDN. This does not test video playback.

Custom presets

Use YAML to check status codes, response headers, body text or download size. A custom preset can also replace a built-in by name.

Example output

Each proxy gets a result with request timings and a reason if the check fails. Use -json for one JSON object per line (NDJSON).

These samples show selected fields from a YouTube check.

JSON outputSample
$proxycheck run -p youtube -json proxies.txt
{
  "proxy": "http://192.0.2.10:8080",
  "check": "youtube",
  "ok": true,
  "total_ms": 284,
  "checked_at": "2026-10-30T12:00:00Z"
}
✓ Check passed284 ms

Both YouTube requests passed.

The error_class field distinguishes timeouts, refused connections, TLS errors and rejected responses.

HTTP API

Start the server, then send a proxy list and preset name to POST /v1/check. Results stream in the same NDJSON format.

proxycheck serve -addr 127.0.0.1:8080API usage ↗

Installation

Requires Git and Go 1.26.10 or later.

Create proxies.txt with one proxy per line. Addresses can be host:port or URLs such as socks5://host:port.
